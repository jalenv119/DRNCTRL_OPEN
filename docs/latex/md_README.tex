This is our final release. With it, we have completed our implementation of a BCI (Brain Computer Interface) controlled drone. We have a UI delivering vital information to the usual, and a threaded command and control implementation for command translation. We targeted a modular style, as to help along future groups who may decide to iterate upon this initial release.\hypertarget{md_README_autotoc_md2}{}\doxysection{\texorpdfstring{Local devlopment / Install Instructions}{Local devlopment / Install Instructions}}\label{md_README_autotoc_md2}

\begin{DoxyEnumerate}
\item Run Emotiv launcher and sign in; ensure it is running as a background process. (Install the Emotiv BCI package as well for training)
\item Create a user headset profile and generate keys/tokens. If the user desires, they can begin headset training at this point
\item Replace the CLIENT\+\_\+\+SECRET, CLIENT\+\_\+\+ID, PROFILE within cortex.\+py. Each of these should have a placeholder currently in the string areas.
\item Run either gui.\+py or cortex.\+py to initialize/cache offline keys.
\begin{DoxyItemize}
\item Due to how the drone is connected, keys must be cached for offline use.
\item If the user wishes to control the drone, after the initial run, they should connect to the drones SSID after powering it on and rerun.
\item If the user does not wish to operate the drone, they can continue with the initial run without concern.
\end{DoxyItemize}
\item For adding new commands, the user can change the option in the cortex file specifying the json commands (ACTION\+\_\+\+TO\+\_\+\+OUTPUT).
\end{DoxyEnumerate}\hypertarget{md_README_autotoc_md5}{}\doxysubsection{\texorpdfstring{Considerations}{Considerations}}\label{md_README_autotoc_md5}
